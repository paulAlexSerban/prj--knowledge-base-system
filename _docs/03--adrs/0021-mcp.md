# ADR 0021: The official MCP SDK, beside the REST API

Status: decided during the build.

## Context

A second agent should not need a custom integration. MCP is the tool protocol those clients already speak. It does not authenticate the caller and it does not enforce access. The server does not use the old FastMCP class name.

## Decision

The MCP server depends on `mcp>=2.3.0` and builds `mcp.server.mcpserver.MCPServer`. The `FastMCP` name was removed in mcp 2. The process listens on port 8001. Tools are `search_knowledge`, `get_document`, `find_related`, and `list_sources`. There is no write tool. Tool text says the snippet is untrusted data. `gateway-core` is the service layer. The REST API on port 8000 is the other adapter. Tool schemas live next to that layer so the two cannot drift. REST `list_sources` is public. MCP requires a bearer token on `/mcp`, including for `list_sources`.

## Alternatives rejected

- REST only. Enough for the chat page, which is what calls it. A notebook agent would then invent its own tool protocol. MCP is the one those notebooks already speak.
- A hand-rolled tool protocol. The same shapes, with none of the clients.
- Treating "the client speaks MCP" as "the call is allowed". Rejected in [ADR 0018](0018-authorization.md).

## Consequences

- MCP clients and the chat page can diverge in which tool they pick. The query router that would stop that is not built. Notebooks `50` and `51` print the model's choice.
- A future rename inside the `mcp` package breaks the import. The server fails at startup with that message rather than booting a second implementation.
